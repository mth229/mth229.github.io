4.1 Introduction

A zero of the function \(f\) is a value \(x\) with \(f(x) = 0\).

Solving for zero of a function is a mathematical skill taught early on. In some cases, such as with linear equations, solving for zeros can be done directly using algebra. Similarly, in the case of factorable polynomials, we are taught to factor and then set each term to 0 to find the possible solutions, utilizing the fact that for the real numbers the product of two numbers is \(0\) only if one or both of the numbers is as well.

However, in general, the problem of finding one (or all) solutions to the equation

\[ f(x) = 0. \]

for an arbitrary \(f\) has no well-defined process.

A related problem is to find one (or all) solutions to an equation of this type:

\[ f(x) = g(x) \]

Conceptually this is identical to the above, as we just set \(aux(x) = f(x) - g(x)\) and solve for when \(aux(x)\) is \(0\).

Here we discuss a few different elementary means to find zeros with Julia, leaving some other methods for a later lesson.

We will use the add-on package Roots which provides implementations of a few zero- and root-finding algorithms. This package is loaded when the MTH229 package is loaded.

using MTH229
using Plots

4.2 Zeros of a polynomial

Univariate polynomials are algebraic expressions involving an indeterminate. Polynomial functions are functions whose body evaluates a polynomial expression. These are special functions, in that their relatively simple form allows for many explicit things to be known. A famous example is the quadratic formula which for polynomials of degree 2 gives an explicit formula for the roots:

\[ \frac{-b \pm \sqrt{b^2 - 4ac}}{2a}. \]

NoteAlert

A “root” of a polynomial is just a polynomial-specific name for a zero of the polynomial viewed as a function.

For example, if we have the quadratic polynomial \(2x^2 + 3x - 2\) we can solve for the roots with:

a = 2; b = 3; c = -2
discr = b^2 - 4*a*c
(-b + sqrt(discr))/(2a), (-b - sqrt(discr))/(2a)
(0.5, -2.0)

If you wanted to write a function to do this, it would be straightforward, save the detail of needing to make a negative number complex in order to take its square root:

## find roots of ax^2 + bx + c
function quadratic(a, b, c)
  discr = b^2 - 4*a*c
  sq = (discr > 0) ? sqrt(discr) : sqrt(discr + 0im)

  [(-b - sq)/(2a), (-b + sq)/(2a)]
end
quadratic (generic function with 1 method)
NoteAlert

This is an example where the function is not type-stable as it returns either real-valued answers or complex-valued answers depending on the values of the input variables. In general, Julia functions avoid this behaviour, as it leads to less performant code.

To find the roots of \(x^2 + x - 1\) we could simply use:

quadratic(1, 1, -1)
2-element Vector{Float64}:
 -1.618033988749895
  0.6180339887498949

There are also such formula for third and fourth degree polynomials. The Abel-Ruffini theorem states there is no solution in radicals to general polynomial equations of degree five or higher with arbitrary coefficients. Galois—at the tender age of 20—demonstrated that, in general, there can be no such formula for the roots of a fifth or higher degree polynomial in a manner showing that \(x^5-x-1\) can be be solved in this manner. There are still many facts known about such polynomials. For example, the Fundamental theorem of algebra states that every real-valued polynomial of degree \(n\) will have \(n\) roots, when we count complex roots and multiplicities.

4.3 Graphical solutions

More generally, the equation \(f(x) = 0\) may not have any special form leading to a known solution. In this case, there are various techniques to find zeros. Here we mention graphing, such as is done with a graphing calculator. In the next section, we discuss the bisection algorithm for root finding.

Finding a zero

The flight of an arrow can be modeled using various functions, depending on assumptions. Suppose an arrow is launched in the air from a height of 0 feet above the ground at an angle of \(\theta = \pi/4\). With a suitable choice for the initial velocity, a model without wind resistance for the height of the arrow at a distance \(x\) units away may be:

\[ j(x) = \tan(\theta) x - (1/2) \cdot g(\frac{x}{v_0 \cos\theta})^2. \]

In Julia we have, taking \(v_0=200\):

j(x; theta=pi/4, g=32, v0=200) = tan(theta)*x - (1/2)*g*(x/(v0*cos(theta)))^2
j (generic function with 1 method)

If we can ignore all the constants, we might recognize \(j(x)\) has the form \(ax - bx^2\), so that it is a parabola that opens downward with one root at \(x=0\).

With a velocity-dependent wind resistance given by \(\gamma\), again with some units, a similar equation can be constructed. It takes a different form:

\[ y(x) = \big(\frac{g}{\gamma v_0 \cos(\theta)} + \tan(\theta)) \cdot x + \frac{g}{\gamma^2}\log(\frac{v_0\cos(\theta) - \gamma x}{v_0\cos(\theta)}\big) \]

Again, \(v_0\) is the initial velocity and is taken to be \(200\) and \(\gamma\) a resistance, which we take to be \(1\). With this, we have the following Julia definition (with a slight reworking of \(\gamma\)):

function y(x; theta=pi/4, g=32, v0=200, gamma=1)
     a = gamma * v0 * cos(theta)
     (g/a + tan(theta)) * x + g/gamma^2 * log((a-gamma^2 * x)/a)
end
y (generic function with 1 method)

Example: Finding a zero

Sometimes, the equation \(f(x)=0\) is actually presented as \(f(x)= g(x)\). This form can be rewritten as \(aux(x) = f(x) - g(x) = 0\), or if working graphically we can just look for crossing points of the graphs of \(f(x)\) and \(g(x)\). Here we shall do that.

We wish to compare two trash collection plans

  • Plan 1: You pay 47.49 plus 0.77 per bag.
  • Plan 2: You pay 30.00 plus 2.00 per bag.

There are some cases where plan 1 is cheaper and some where plan 2 is. Categorize them.

Both plans are linear models and may be expressed in slope-intercept form:

plan1(x) = 47.49 + 0.77x
plan2(x) = 30.00 + 2.00x
plan2 (generic function with 1 method)

Assuming this is a realistic problem and an average American household might produce 10-20 bags of trash a month (yes, that seems too much!) we plot in that range:

plot(plan1, 10, 20)
plot!(plan2)

We can see the intersection point is around 14 and that if a family generates between 0-14 bags of trash per month that plan 2 would be cheaper, otherwise they should opt for plan 1.

4.4 Bisection algorithm

The last example had us graphically “zoom” in on a zero, and led us to an estimate to \(1\) or \(2\) decimal points. Trying to get more accuracy than that graphically is at best tedious. Here we discuss a method to get as much accuracy as is numerically possible based on the intermediate value theorem:

The intermediate value theorem: If \(f(x)\) is a continuous function on \([a,b]\) then at some point in the interval \(f(x)\) takes on any value between \(f(a)\) and \(f(b)\).

In particular if \(f(x)\) is continuous with \(f(a)\) and \(f(b)\) having different signs then there must be a point \(c\) in \([a,b]\) where \(f(c) = 0\). (When \(f(a)\) and \(f(b)\) have different signs, we say \(a\) and \(b\) bracket a root.) This observation is due to Bolzano.

The bisection algorithm finds a zero between two bracketing values, as illustrated in this graphic:

plot(sin, 1, 5)
plot!(zero)
vline!([3,4])

The zero of the sine function at \(\pi\) is clearly between \(3\) and \(4\). The bisection algorithm is a method to refine the bracketing interval so that it is as small as possible.

The bisection algorithm utilizes Bolzano’s observation. It is a simple iterative procedure for finding such a value \(c\) when we have a continuous function and a bracketing interval.

NoteAlert

The bisection method does not work when the function does not cross the \(x\) axis at the root. For example, the zero at \(0\) of \(f(x) = x^2 e^x\) would not be found with this method. This is why a bracketing interval is needed to start the algorithm.

Mathematically the basic idea is simple.

Starting with \([a,b]\), the midpoint \(M = (a + b)/2\), is tested for its function value. If \(f(M) = 0\), great, we are done. If it has opposite sign of \(f(a)\), then a root must be in the interval \([a,M]\), so the problem is reduced a smaller interval. Otherwise, it has opposite sign of \(f(b)\) and the problem is reduced to \([M,b]\). Either way, the algorithm is repeated for the smaller interval where a root is known. As each step halves the interval length, it must eventually converge to an answer.

Graphically, we could do this. For example, Let’s consider \(f(x) = x^2 - 2\) with the bracketing interval \([1,2]\). We first plot:

f(x) = x^2 - 2
a,b = 1, 2
plot(f, 0, 3; legend=false)
plot!(zero)
vline!([a, (a+b)/2, b])  # add vertical lines at a, b and midway

We can see that \(c = (a + b)/2 = 3/2\) will have \(f(c) > 0\), so the new bracket is \([a,c]\):

a, b = a, (a + b)/2

plot(f, a, b; legend=false)
plot!(zero)
vline!([(a+b)/2])

Now the function value at the midpoint is negative, so we modify a:

a, b = (a + b)/2, b

plot(f, a, b; legend=false)
plot!(zero)
vline!([(a+b)/2])

And again, this has a function value at the midpoint in the negative territory so again we modify a:

a, b = (a + b)/2, b

plot(f, a, b; legend=false)
plot!(zero)
vline!([(a+b)/2])

And now, as the midpoint is in positive territory we would modify \(b\) …

This gets tedious to do graphically. But it can be easily programmed. The main step might look something like this:

f(x) = x^2 - 2
a, b = 1, 2

c = (a + b) /2

if f(a) * f(c) < 0
  a, b = a, c
else
  a, b = c, b
end
a, b
(1, 1.5)

Though some check if f(c) == 0 is also needed.

Here \(c=1.5\) and the new interval is \([1.0, 1.5]\), as we had graphically. We just need to repeat the above.

It seems as though we could be here all day. Indeed, if doing this by hand it might take up quite a bit of time. We should automate this. Before automating this, we need to think: when would we stop?

Mathematically we can keep taking halves using the concept of a limit. See for example Zeno’s paradox. On a computer we don’t have such a luxury. In fact, for floating point numbers we couldn’t keep taking halves—even if we wanted—as ultimately we should expect to get a and b being floating point values that are next to each other – and hence there is no midpoint. (Well, there are some cases that suggest a more careful numeric approach to the above.)

So even though this doesn’t make mathematical sense we can try stopping when the following condition is no longer true:

a < c < b
false

A while loop is used to repeat the central step until the above (or some variant) is false.

The MTH229 package has a bisection method implemented for this which also outputs a graphical indication of the first few steps taken.

Okay, let’s look at the function \(f(x) = -16x^2 + 32x\). We know that \(0\) and \(2\) are roots. Let’s see if our algorithm finds them:

f(x) = -16x^2 + 32x
bisection(f, -1, 1) ## should find 0

a###############################################################b
... exact answer found ...
0.0
bisection(f, 1, 3)  ## should find 2

... exact answer found ...
2.0

Okay, it seems to work. Lets try it on a less trivial problem. We know \(\sin(x)\) and \(\cos(x)\) cross in the interval \([0, \pi/2]\). If we are too tired to remember where, we can simply ask:

f(x) = cos(x) - sin(x)
x = bisection(f, 0, pi/2)

Is x really a zero?

(0.7853981633974483, 1.1102230246251565e-16)

Hmm, the answer is 1.1102230246251565e-16. So technically this is not a zero. But computationally it is a zero! First it should be clear that it is really close to zero. We will see it is as close as computationally possible to a zero.

The nextfloat and prevfloat functions find the floating point values just bigger than x and just smaller. In this case we have that f(x) and f(nextfloat(x)) have different signs:

f(x),  f(nextfloat(x))
(1.1102230246251565e-16, -1.1102230246251565e-16)

So \(f\) is crossing \(0\) between the value we found, x and, the floating point value just a bit bigger. We can’t realistically expect to get any closer than that, as there are no machine numbers in between these two.

4.5 The Roots package and fzero to solve \(f(x) = 0\)

The bisection method, while easy to describe and understand, can be made a bit more efficient. The fzero function from the Roots package does so. This package is loaded when MTH229 is. This function uses a tuple to specify the bracketing interval.

For example, to find a zero of \(f(x) = 2x \cdot \exp(-20) - 2 \cdot \exp(-20x) + 1\) in the bracketing interval \([0,1]\) we have:

f(x) = 2x * exp(-20) - 2 * exp(-20x) + 1
fzero(f, 0, 1)
0.03465735902085385
Notefind_zero

In the Roots package, fzero is an alias to the find_zero function. We use it hear to save typing and inertial. The find_zero function is actually an interface to various root-finding algorithms. The find_zero function uses a container to specify the bracketing interval, like (a,b). The fzero function also supports that alternate form, though we use fzero(f, a, b), as that is the same pattern as used by plotting.

The bracketing interval can also be specified as a tuple, as in (0,1) which can offer some convenience, but isn’t necessary for interactive usage.

4.5.1 From a graph to a more accurate numeric answers

One needs to know where to look in order to use the bisection method. The basic “one-two punch” is:

  • graph the function to identify bracketing values for which the zero is between \(a\) and \(b\). These need not be very precise, indeed for some problems \(a\) and \(b\) can even be infinite.

  • use the bisection method to find the zero to many decimal points.

Here we illustrate with the problem of finding all intersection points of \(e^x = x^4\) over the interval \([0,10]\).

Recall, solving for \(f(x) = g(x)\) is identical to the problem of solving \(aux(x) = 0\), where we define \(aux(x) = f(x) - g(x)\). So our problem is to find solutions to \(e^x - x^4 = 0\).

A quick plot shows that the function has such a wide range that looking over the entire domain at once will be problematic:

f(x) = exp(x) - x^4
plot(f, 0, 10)

The function is an exponential and a polynomial. A basic fact is that eventually exponentials grow faster so \(f(x)\) will rapidly head towards \(+\infty\), a fact that can be easily be observed bu plotting over a wider interval, such as \([0, 20]\). However, at \(0\) we easily see that \(f(x)\) is positive, it being \(1-0\). So if the function dips negative, it must come back up, so we expect \(2\) zeros. From the initial graph, it appears we can find them between \([0,7.5]\) and between \([7.5, 10]\).

So we find the values of the zero in the bracketed region \([7.5, 10]\):

fzero(f, (7.5, 10))
8.6131694564414

The root within \([0, 7.5]\) is found with:

fzero(f, (0, 7.5))
1.4296118247255556

We do this again. Find a zero of the function f(x) = asinh(x) - e^2.

As we don’t know much about this function, we first plot over \([-10,10}\):

f(x) = asinh(x) - e^2
plot(f, -10, 10)

If we believe that the function is increasing, we can see then that any zero happens far to the right of \(10\). Seeing this, we replot over \([0,1000]\):

plot(f, 0, 1000)

From the graph, we confirm that \([0,1000]\) contains a zero and is a bracketing interval. With this, we are ready to call fzero:

fzero(f, 0, 1000)
809.0886869668318

4.5.2 Solving \(f(x) = c\)

There are two reasonable means to solve \(f(x) = c\) for \(x\) when \(c\) is non-zero. As above, we can define a new function \(aux(x) = f(x) - c\). Then when \(aux(x)\) is \(0\) we will have \(f(x)\) equal to c.

Alternatively, we can pass in \(c\) as a parameter by defining a two-argument version of \(f.\)

Suppose we aim to find when \(\tan(x) = c\) for \(c > 0\). For any \(c > 0\), say \(c = 1.23\), we can see from the shape of the graph of \(\tan(x)\) that there is one intersection point between \(0\) and \(\pi/2\).

The easiest way is to create a simple function:

aux(x) = tan(x) - 1.23
fzero(aux, 0, pi/2)
0.8881737743776796

We can be more formal (as it is a more general pattern) and use two functions to define the problem:

f(x) = tan(x)
g(x) = 1.23
aux(x) = f(x) - g(x)
fzero(aux, 0, pi/2)
0.8881737743776796

We compare with the arc tangent, as there is a built-in function to do this particular problem:

atan(1.23)
0.8881737743776796

An alternate approach is to define our function with a parameter:

f(x, p) = tan(x) - p

We can then pass values for p to fzero to solve:1

4.5.3 Solving \(f(x) = g(x)\)

The fzero function finds a value solving \(f(x) = 0\). When the question involves two functions, e.g. \(f(x) = g(x)\) it can’t be immediately used. However, forming an auxiliary function \(aux(x) = f(x) - g(x)\) works as solutions to \(aux(x) = 0\) satisfy \(f(x) = g(x)\).

For example, identifying when \(\cos(x) = 2x\) may be of interest. By simple geometry, the line through zero with positive slope will intersect the cosine graph somewhere in \([0, \pi/2]\):

We find where with the following approach:

f(x) = cos(x)
g(x) = 2x
aux(x) = f(x) - g(x)

fzero(aux, 0, pi/2)
0.45018361129487355

More generally, we might be interested in solving \(\cos(x) - px\) for different \(p > 0\). The parameter approach can be readily used:

Example

The secant(f, a, b) function returns a function representing the secant line between \((a, f(a))\) and \((b, f(b))\). In the following we see where the secant line between \(1\) and \(2\) intersects that between \(-2\) and \(-1\) for \(f(x) = e^x\).

Graphically, we have

f(x) = exp(x)
plot(f, -2.1, 2.1; legend=false, ylims=(0, 10))
plot!(secant(f, 1, 2))
plot!(secant(f, -2, -1))

The intersection point near \(0.5\) is clear. In the following we show how an infinite bracketing interval is possible. As two non-parallel lines intersect in one point, any open interval containing the intersection point will be a bracketing interval. The bisection algorithm of fzero handles without fuss any signed value, even infinite ones (though does stop if it encounters a NaN value).

f(x) = exp(x)
sl_12 = secant(f, 1, 2)
sl_21 = secant(f, -2, -1)
aux(x) = sl_12(x) - sl_21(x)
fzero(aux, -Inf, Inf)
0.5752103826044416

The above follows the pattern of using aux(x)= f(x) - g(x) to solve \(f(x) = g(x)\). The intermediate names, sl12 and sl21, are used for the two function here that we are finding the intersection of.

4.5.4 Using an equation to solve \(f(x) = g(x)\)

Symbolic math is touched on in section 5 using the powerful SymPy package. In anticipation we mention an alternate way to solve an equation \(f(x) = g(x)\) using a symbolic variable.

The MTH229 package loads the SimpleExpressions package which provides a means to create a basic symbolic variable (and parameter) through the macro @symbolic. SymPy will uses the more powerful @syms macro for a related task.

With a symbolic variable, computed expressions stay symbolic until needed. Symbolic expressions can be paired together with a ~ to create a symbolic equation. Such equations can be solveed with the solve function. While SymPy can solve symbolic equations for algebraic answers, SimpleExpressions uses fzero behind the scenes.

So to solve when \(\cos(x) = 2x\) we might have:

@symbolic x  # make a symbolic variable
eq = cos(x) ~ 2x
fzero(eq, 0, pi/2)
0.45018361129487355

(In the above, cos(x) and 2x are examples of symbolic expressions.)

To solve an equation like \(f(x) = c\), \(c\) possibly zero is straightforward. For example we might have something like this:

f(x) = x * tanh(exp(x))
c = 1/2
fzero(f(x) ~ c, -5, 5)
0.5341051912972407

(In the above, applying f(x) to the symbolic x leaves a symbolic expression.)

To solve an equation like \(f(x) = g(x)\), when two secant lines intersect, we have:

f(x) = exp(x)
sl_12 = secant(f, 1, 2)
sl_21 = secant(f, -2, -1)
fzero(sl_12(x) ~ sl_21(x), -Inf, Inf)
0.5752103826044416

For such symbolic equations, the plot function plots both the left and right hand sides, so we could visualize the above with:

plot(f, -2.25, 2.25)
plot!(sl_12(x) ~ sl_21(x))

The rule of signs of Descartes is a simple means to give an upper bound on the number of positive real roots a polynomial has. One counts the number of sign changes amongst the polynomials coefficients. Suppose this is \(k\), then the number of positive real roots (counting multiplicities) is one of \(k\), \(k-2\), \(k-4\), … . In particular if \(k\) is odd, there must be at least one real root.

For example, the polynomial \(x^3 -x^2 -x - 1\) has signs + - - -, so there is just one sign change. This implies there must be exactly one positive real root, which is identifyied with:

f(x) = x^3 -x^2 -x - 1
N.(sympy.real_roots(f(x)))
1-element Vector{Float64}:
 1.8392867552141612
